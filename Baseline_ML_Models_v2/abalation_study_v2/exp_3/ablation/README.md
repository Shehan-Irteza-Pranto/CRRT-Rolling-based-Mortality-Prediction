# Preprocessing ablation of the machine-only ensemble

The parent ablation swept preprocessing on single models (DecisionTree 1-day, RandomForest 2-day).
This repeats it on the **best machine-only model — the ensemble** (rich-classical GradientBoosting +
RandomForest + attention-CNN1D, probability-averaged), so the preprocessing conclusions hold for the
model actually used.

**Method.** For each cleaning configuration we rebuild the 200-feature rich table and the CNN signal
from that configuration's per-minute pressure, retrain the ensemble (fixed-HP classical, 3 seeds each
branch), and report held-out **test AUROC** (+ patient-bootstrap 95% CI) for 1-day and 2-day.
Base-133 feature tables are reused from `exp_2/ablation/data/`; LOO streams are regenerated by
`gen_loo_streams.py`. Driver: `ensemble_ablation.py` (reuses `paper_materials/machine_only_pipeline.py`).
Results: `results/ablation_ensemble.csv`.

> Note: this fixed 3-component recipe (rich-GB + rich-RF + CNN, 3 seeds) gives a slightly lower
> reference than the headline ensemble:mean (current_denoised 0.633 here vs 0.649 headline), but the
> recipe is identical across configurations, so the **relative** ablation comparison is valid.

## A. Denoise-variant sweep — ensemble test AUROC
downtime strategy (current = flat; Th70/80/90 = dose at 0.70/0.80/0.90) × peak handling.

**1-day**
| variant | denoised | noised |
|---|--:|--:|
| current | **0.633** | 0.592 |
| Th70 | 0.619 | 0.583 |
| Th80 | 0.604 | 0.608 |
| Th90 | 0.599 | 0.609 |

**2-day**
| variant | denoised | noised |
|---|--:|--:|
| current | 0.642 | 0.615 |
| Th70 | 0.632 | 0.619 |
| Th80 | 0.635 | 0.641 |
| Th90 | **0.659** | 0.656 |

> Note: this sweep uses a light 3-component, 3-seed recipe (reference current_denoised = 0.633), so
> its `all3` did **not** reproduce the headline. For the leave-one-out we therefore use the
> **anchored** version below.

## B. Leave-one-out — ANCHORED to the headline ensemble (`anchored_loo.py`)
This is the LOO you want: `all3` reproduces the **headline best ensemble** because it uses the same
stream (flat downtime + peak removal) **and** the full recipe (tuned base+rich classical, 5 models ×
5 seeds, + attention-CNN1D, val-ranked ensemble:mean). `all3` reuses the headline result; each other
config reruns the full pipeline on the stream with that one cleaning step **left in** (kept).

| config (cleaning step kept in) | 1-day AUROC | Δ vs all3 | 2-day AUROC | Δ vs all3 |
|---|--:|--:|--:|--:|
| **all3** (all removed = headline) | **0.649** | — | **0.643** | — |
| no_priming (keep priming) | 0.640 | −0.009 | 0.640 | −0.003 |
| no_downtime (keep downtime) | 0.612 | **−0.037** | 0.643 | 0.000 |
| no_peak (keep alarm peaks) | 0.615 | **−0.034** | 0.621 | **−0.022** |

(95% CIs in `results/anchored_loo.csv`.)

## Takeaways
- **Removing all three artifacts (`all3`) is best**, and it reproduces the headline ensemble
  (1-day 0.649 / 2-day 0.643) — the LOO is correctly anchored.
- **At 1-day, downtime removal (−0.037 if kept) and peak removal (−0.034) are the two big
  contributors**; priming removal is small (−0.009). So the clean signal the model relies on comes
  mostly from stripping machine downtime and alarm peaks.
- **At 2-day, peak removal is the main contributor (−0.022)**; downtime removal is neutral
  (0.643 either way) and priming negligible — the higher-prevalence label is less sensitive to
  downtime.
- **Why the earlier (non-anchored) LOO barely moved**: it used the dose-downtime baseline (≠ the
  flat-downtime headline stream) and a light ensemble recipe, so `all3` read 0.608 not 0.649 and the
  deltas were compressed. Anchoring (flat downtime + full recipe) restores the true, interpretable
  leave-one-out deltas above.
- **Denoise sweep (Table A)**: robust band (1-day 0.59–0.63, 2-day 0.62–0.66); peak removal helps
  most at 1-day; Th90 marginally best at 2-day. (Light recipe — relative comparison only.)
